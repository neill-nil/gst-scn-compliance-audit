# NoticeCheck: checking GST show cause notice procedure with a small model

NoticeCheck reads the record of a GST demand proceeding under sections 73/74 of the CGST Act (show cause notice →
reply → personal hearing → demand order) and checks each procedural step the law requires. For every one of 13
defect types it answers **defect**, **no defect**, **contested** (courts disagree) or **can't tell**, cites the
section, quotes the record, lists missing facts, and decides whether a professional should take over. It checks
procedure only, never whether tax is owed.

LMA Group Project 2026, team Bleed Tokens. Final results, explained: [`docs/results/RESULTS.md`](docs/results/RESULTS.md); every table: [`docs/results/RESULTS_TABLES.md`](docs/results/RESULTS_TABLES.md)
(generated by `scripts/final_analysis.py`; machine-readable copy in `runs/final/summary.json`).

## Setup
```
git clone -b main https://github.com/neill-nil/gst-scn-compliance-audit.git
cd gst-scn-compliance-audit
pip install -r requirements.txt            # jsonschema, duckdb, pandas; pytest for the tests
sudo apt-get install poppler-utils         # pdftotext
python scripts/fetch_data.py               # all in-scope judgments (~4,800 texts, ~450 PDFs), sha256-checked, 10-15 min
python -m src.tools.caselaw                # case-law index (precedent split only)
python -m pytest -q tests                  # tool tests
```
Model access (only for re-running models; every result is already in `runs/`):
- **Gemini** (drafting, B2, NoticeCheck+Gemini): put `GEMINI_API_KEY=...` and `GEMINI_MODEL=gemini-3.5-flash-lite` in `.env` (see `.env.example`).
- **Qwen3-8B** (B1, NoticeCheck): an OpenAI-compatible server, e.g. Ollama `qwen3:8b`; set `LOCAL_BASE_URL`, `LOCAL_MODEL=qwen3:8b`.
  We ran it on Kaggle's free T4 GPUs: step-by-step notebooks in [`docs/team_plan/noticecheck_kaggle.md`](docs/team_plan/noticecheck_kaggle.md).
- **Fine-tuning (RQ2)**: Unsloth on a Kaggle T4, notebooks E–H in [`docs/team_plan/rq2_kaggle.md`](docs/team_plan/rq2_kaggle.md).

## Reproducing the results
```
# 1. answer key and inputs (gold is committed; this rebuilds it from the reviews)
python -m scripts.build_gold
python -m src.baselines.inputs --gold data/gold/records.jsonl --out data/interim/inputs     # full_record, notice_only, raw_text
python -m scripts.build_dev_inputs

# 2. systems (outputs already in runs/)
python -m src.baselines.b0_rules --input data/interim/inputs/full_record.jsonl --out runs/b0_v2/outputs.jsonl
python -m src.baselines.b1_plain --input data/interim/inputs/full_record.jsonl --out runs/b1_v2/outputs.jsonl     # needs Qwen server
python -m src.baselines.b2_frontier --input data/interim/inputs/full_record.jsonl --out runs/b2_v2/full_record.jsonl \
       --provisions data/corpus/provisions_b2.json                                                                 # needs Gemini
python -m src.noticecheck.cli --inputs data/interim/inputs/full_record.jsonl --config configs/nc_full.json \
       --run-id nc_full_s1 --seed 1                                                                               # also nc_no_*.json, nc_full_gemini.json

# 3. RQ2 (Kaggle): build data, train, extract, score
python -m scripts.build_rq2_data
python -m src.rq2.train --out runs/rq2_lora                     # GPU
python -m src.rq2.extract --run-id rq2_tuned --adapter runs/rq2_lora/adapter
python -m eval.score_extraction --system base=runs/rq2_base --system tuned=runs/rq2_tuned --system gemini=prefill --repair
python -m scripts.build_e2e_inputs --run runs/rq2_tuned         # then NoticeCheck on runs/rq2_tuned/checker_full_record.jsonl

# 4. scores, comparisons and the final tables
python -m eval.score --run runs/nc_full_s1 --split test --strict --no-unargued-as-rejected
python -m scripts.compare_runs --system runs/nc_full_s1 --baseline runs/b1_v2 --strict
python -m scripts.component_metrics                               # tool calls, verifier, retrieval -> runs/final/components.json
python -m scripts.final_analysis                                 # writes docs/results/RESULTS_TABLES.md and runs/final/summary.json
```
The fine-tuned LoRA weights (175 MB, `runs/rq2_lora/adapter/`, base `unsloth/Qwen3-8B-unsloth-bnb-4bit`, rank 16) are
too large for GitHub and are kept outside the repository; `runs/rq2_lora/train_log.json` records the training run.

## Results in brief (125 test cases)
| System | F1 | Strict F1 (right section) | Unargued flags |
|---|---|---|---|
| B0 rules | 0.27 | – | 1 |
| B1 Qwen3-8B, record only | 0.40 | 0.19 | 88 |
| B2 Gemini + statute | 0.50 | 0.38 | 14 |
| **NoticeCheck (Qwen3-8B), 3 runs** | **0.42–0.51** | **0.42–0.51** | **29–33** |
| NoticeCheck with Gemini | 0.51 | 0.51 | 14 |
| Full system end to end (fine-tuned extractor → NoticeCheck) | 0.38 | 0.38 | 31 |

Fine-tuning the extractor raised fact-field F1 from 0.52 to 0.80 (0.88 with cut-off outputs repaired). Details,
confidence intervals, ablations, error analysis, the held-out court and the fresh-case check are in
[`docs/results/RESULTS.md`](docs/results/RESULTS.md).

## Limitations
No real show cause notices are public, so every input is the proceeding as described in a High Court judgment, and
the court's rulings are the answer key. Judgments often state conclusions without the underlying facts, which caps
recall for every system. The answer key was drafted by Gemini and corrected by the team, which may favour the
Gemini baseline.
